# Sprint 3B.01 — Check Coverage and Execution Lifecycle

The machine-readable inventory is [sprint3b01-check-coverage.csv](sprint3b01-check-coverage.csv). It is generated by `scripts/generate_check_coverage_matrix.py` from the current AL catalog and `DH Deep Scan Runner`, and is guarded by a backend source-contract test.

At this commit, the inventory has 199 checks: 193 aggregate-count routes and six duplicate-group routes. Every enabled route persists `STARTED` before its evaluation group runs. A successful scan accepts only `PASS` or `FINDINGS` for every enabled expected check; an absent observation never implies `PASS`.

On a failure, `STARTED` checks are persisted as `FAILED`. A check that the runner can prove was never reached is persisted as `NOT_EXECUTED`; disabled checks are `SKIPPED`. Checks in a group whose start cannot be proved are intentionally absent from the failure evidence rather than assigned an invented terminal status. Failed scans remain failed even when some checks produced findings.

Backend evidence is tied to the original lease, tenant, company, expectation snapshot, and canonical retry payload. Completed historical scans cannot be retrofitted with evidence. This sprint does not alter Sprint 3B.02's provenance or record-identity boundary.

## Runtime limitation

The static contract and backend tests are not BC27 runtime evidence. In-place upgrade, non-SUPER execution, interrupted-group behavior, and positive/negative full scans in the dedicated BC27 sandbox remain open acceptance gates.
